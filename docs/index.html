Pakistan Stock Exchange / market data API

PSX Market Data APIs

A complete field guide to the cached PSX quote, market, index, history, EOD, authentication, compatibility, and operational APIs.

Run your first request Browse endpoints
Data policy Responses are cache-backed. Always surface the returned freshness metadata and source notice to downstream consumers.

Overview

What this service exposes

The API reads normalized data from a local database. A separate worker fetches public PSX Data Portal pages, parses them, and persists snapshots. User requests never scrape PSX directly.

26documented HTTP endpoints: 25 GET and 1 POST
2supported history intervals: int and eod
4authentication modes

Core v1

Stable, typed endpoints under /v1 for health, market snapshots, symbols, quotes, history, EOD, and indices.

Compatibility layer

Root-level endpoints retained for clients using the original psx-data-hub contract, including token issuance and aggregate metrics.

Quick start

Local API plus worker

Install

git clone https://github.com/zawster/psx-data-hub.git
cd psx-data-hub
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env

Start the API

$env:PYTHONPATH="src"
uvicorn psx_data_hub.main:app --reload --no-server-header

The interactive OpenAPI UI is available at http://127.0.0.1:8000/docs when DOCS_ENABLED=true.

03

Populate data

$env:PYTHONPATH="src"
python -m psx_data_hub.worker

The API can start before the worker, but market endpoints return empty or no_data payloads until the first successful cycle.

curl http://127.0.0.1:8000/v1/health
curl http://127.0.0.1:8000/v1/market
curl http://127.0.0.1:8000/v1/stocks/PSO

Authentication

AUTH_MODE controls protected routes

/v1/health, /v1/status, /, and /token are public. Market-data routes use the configured policy. /token-check always requires a valid bearer token.

API key request

curl http://127.0.0.1:8000/v1/market \
  -H "X-API-Key: your-api-key"

JWT token flow

curl -X POST http://127.0.0.1:8000/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=demo&password=demo"

curl http://127.0.0.1:8000/v1/market \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"

Configure users as comma-separated username:password:scope1|scope2 entries in LEGACY_USERS. Plain passwords are hashed at application startup; pre-hashed bcrypt values are accepted.

Conventions

Shared request and response rules

Base URLs

Local: http://127.0.0.1:8000

Core prefix: /v1

Compatibility routes use the root path.

Symbols and dates

Symbols are normalized to uppercase and must match [A-Z0-9._-]{1,20}. Datetimes use ISO 8601. EOD dates use YYYY-MM-DD.

Delay metadata

Quote, market, and compatibility responses include delay metadata directly or under delay.

{
  "delay_minutes": 5,
  "source": "dps.psx.com.pk",
  "source_timestamp": "2026-08-04T10:30:00Z",
  "fetched_at": "2026-08-04T10:35:03Z",
  "cache_age_seconds": 12,
  "data_source_notice": "<configured data-source notice>",
  "is_stale": false
}

HEAD requests

Every GET endpoint also accepts HEAD. The response body is empty and headers, including the GET-equivalent Content-Length, are preserved. Use curl --head URL, not curl -X HEAD URL.

Errors and limits

Consistent HTTP behavior
400

Invalid symbol or reversed date range.

401

Missing or invalid API key or bearer token.

403

A JWT-only operation received another principal type.

404

Requested quote, company, or index is not cached.

422

Missing form/query fields, invalid dates, interval, or limits.

429

Minute or burst rate limit exceeded.

Error body

{ "detail": "no cached quote for symbol 'UNKNOWN'" }

Rate-limit body

{
  "error": "rate_limit_exceeded",
  "message": "Too many requests. Lower polling frequency and retry later."
}

Rate limiting identifies clients by bearer token, API key, or direct peer IP. X-Forwarded-For is used only when the immediate peer is listed in TRUSTED_PROXIES. Health and service-status paths are exempt.

Architecture

Cache-backed by design

1. Provider

Fetches four market pages concurrently, normalizes quotes, indices, market totals, and sectors, and parses JSON time series.

2. Worker

Runs the provider, persists all market-watch quotes, refreshes watchlist time series, and prunes old quote rows.

3. Repository

Stores symbols, quotes, market snapshots, history points, and EOD records through async SQLAlchemy.

4. API

Reads cached rows only, applies auth and rate limits, and decorates responses with delay and staleness metadata.

SQLite initialization

init_db() creates missing tables, removes duplicate non-null quote timestamps, and creates the named unique index uq_stock_quote_symbol_ts. Large history and EOD writes use batches of 75 rows to stay below SQLite variable limits.

Provider failure behavior

Temporary fetch and parse errors are retried by the service. Sector labels are a soft dependency and retain the last successful mapping. Worker failures are logged per operation so one symbol does not terminate the entire polling loop.

Deployment

API and worker are separate processes

Production checklist

  • Back up an existing SQLite database before the first v0.2.0 startup.
  • Set ENV=production, a strong JWT_SECRET_KEY, explicit ALLOWED_ORIGINS, and DEBUG=false.
  • Select and test AUTH_MODE; do not assume core routes remain public.
  • Run one API process and at least one worker process against the same database.
  • Use --no-server-header when invoking Uvicorn directly.
  • Monitor /v1/health and alert on database degradation or excessive market-fetch age.
  • Surface the delay notice and stale flag in consuming applications.

Compliance posture

The project does not ship a PSX data license. Public data terms and redistribution rules can change. Respect source terms, avoid guaranteed or premium-data claims, publish cache age and source notices, and obtain independent legal review for commercial redistribution.
